# 6. Project Knowledge

## Project 1: Multimodal RAG — Health Insurance Policy Application

GitHub:
https://github.com/uma-goud/health_insurance_rag_application

### Project Overview

I built a question-answering application using a health insurance policy document from SBI General Insurance.

The main goal was to allow users to ask questions about the policy in natural language and receive answers based on the document rather than manually searching through a lengthy PDF.

### Technologies

- Python
- LangChain
- Gemini API
- Gemini Embeddings
- ChromaDB
- Streamlit
- DeepEval

### How It Works

1. The application takes a health insurance policy PDF as input.
2. It extracts text and relevant images from the document.
3. Image captions are generated and incorporated alongside the extracted text.
4. The content is split into chunks of approximately 1000 characters with 150 characters of overlap.
5. Gemini embeddings are generated using `models/gemini-embedding-001`.
6. The embeddings are stored in ChromaDB.
7. When a user asks a question, the application retrieves relevant document content.
8. The retrieved context is provided to Gemini to generate a grounded answer.
9. The Streamlit interface displays the answer and retrieved source information.

### Additional Implementation Details

- ChromaDB collection: `insurance`
- Persistent vector storage: `./vectorstore`
- Metadata includes source, section, has_image and content_type.
- SQLRecordManager with SQLite is used for indexing management.
- The retriever uses similarity search with a configured top-k value.
- The application supports document indexing, chatting and clearing chat history.

### RAG Evaluation

I explored DeepEval to evaluate the quality of the RAG application.

Results from a previous evaluation run:

- Faithfulness: 1.000
- Answer Relevancy: 1.000
- Contextual Precision: 1.000
- Contextual Recall: 1.000

These are results from a particular evaluation run, not guaranteed production performance.

### What I Learned

I learned how document ingestion, chunking, embeddings, vector databases and retrieval work together to build a RAG application.

I also understood the importance of evaluating whether generated answers are grounded in retrieved information.

### Limitations and Future Improvements

Potential improvements include better retrieval strategies, reranking, more comprehensive evaluation, additional safeguards against unsupported answers and performance optimisation.

Do not claim these improvements are already implemented.

## Project 2: Customer Churn Alert Agent

GitHub:
https://github.com/uma-goud/customer_churn_project

### Project Overview

This project analyses customer activity and identifies customers who may be at risk of leaving a platform.

Instead of relying on one agent to investigate everything, I explored a multi-agent approach where specialised agents examine different aspects of customer behaviour.

### Technologies

- Python
- LangGraph
- LangChain
- Deep Agents
- Gemini API
- SQLite
- SQL Toolkit
- Pydantic

### Architecture

The application uses a supervisor agent and three specialised agents:

1. Review Agent
   - Examines customer reviews and ratings.
   - Identifies negative feedback and dissatisfaction.

2. Authentication Agent
   - Examines login and logout activity.
   - Checks inactivity and login frequency.

3. Support Agent
   - Examines support tickets.
   - Identifies unresolved issues and recurring complaints.

### How It Works

1. Customer activity data is stored in an SQLite database.
2. The supervisor receives the analysis request.
3. It delegates the relevant investigation tasks to specialised agents.
4. Each agent uses SQL tools to retrieve relevant information.
5. The agents return their findings.
6. Intermediate results are stored in a workspace as structured information.
7. The supervisor combines the findings into a final report.
8. Pydantic models help structure the output.

### Risk Classification

The project uses evidence from three areas:

- Reviews
- Authentication activity
- Support tickets

The risk classification is based on how many sources contain relevant churn indicators:

- Evidence in all three sources: Very High
- Evidence in exactly two sources: High
- Evidence in exactly one source: Medium

### Important Clarification

This is an evidence-based AI agent system. It is not a trained machine learning churn prediction model.

### What I Learned

I learned how a supervisor can delegate tasks to specialised agents, how agents can use database tools, and how structured outputs help combine results.

### Future Improvements

Potential improvements include a dashboard, human approval workflows, more advanced risk scoring, monitoring and deployment.

These are future possibilities, not completed features.
